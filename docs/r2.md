# Cloudflare R2 as the store

R2 charges nothing for egress, so a cache in R2 can be public: CI jobs push
with S3 credentials, and everyone else, laptops, self-hosted runners, other
repositories, reads it over plain HTTPS with no account at all.

R2 public buckets serve objects but refuse anonymous `ListObjectsV2`, so
hestia does not list: writers maintain an index of head names next to the
data, and readers fetch that one object. Nothing beyond public read has to
be enabled. R2 implements conditional writes, so writers rewrite that index
with a compare and swap and concurrent pushes never drop each other's
heads.

## 1. Create the bucket

Dashboard: **R2 Object Storage** then **Create bucket**. With
[wrangler](https://developers.cloudflare.com/workers/wrangler/):

```console
$ wrangler r2 bucket create hestia-cache
```

The bucket's **Settings** tab shows the S3 endpoint writers use:

```
https://<ACCOUNT_ID>.r2.cloudflarestorage.com/hestia-cache
```

## 2. Create a token for the writers

**R2** then **API** then **Create User API token**, permission **Object Read
& Write**, scoped to this bucket. Cloudflare shows an access key ID and a
secret once. Store both as repository secrets, for example `R2_ACCESS_KEY_ID`
and `R2_SECRET_ACCESS_KEY`.

## 3. Turn on public reads

Either enable the **Public Development URL** on the bucket (Settings then
Public Development URL then Enable, confirm with `allow`), which gives a
`https://pub-<id>.r2.dev` address, or, better for real use, connect a custom
domain. The development URL is rate limited and bypasses the Cloudflare
cache, so every read hits R2 itself. A custom domain caches, and hestia's
writes already carry the `Cache-Control` a cache should honour: content
addressed objects for a year as `immutable`, heads and the index for 30
seconds.

## 4. Push from CI

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write # only for trust: same-repo or strict
    steps:
      - uses: actions/checkout@v6
      - uses: NixOS/nix-installer-action@main
      - uses: Mic92/hestia@v3
        with:
          s3: s3://hestia-cache
          s3-endpoint: https://<ACCOUNT_ID>.r2.cloudflarestorage.com
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_ACCESS_KEY }}
          AWS_REGION: auto
      - run: nix build .#
```

`AWS_REGION: auto` is what R2 signs with. Several repositories can share one
bucket by giving each a prefix (`s3://hestia-cache/<repo>`); roots already
keep their branches apart inside a store.

Pull requests from forks have no secrets, so they push nothing. To let them
read, point them at the public URL instead, see below. Since a bucket has no
per-branch scopes, use `trust: same-repo` (or `strict`) so readers only
accept heads attested by this repository's workflows, see
[signing](signing.md).

## 5. Read without credentials

Anywhere, including jobs and machines that must not be able to write:

```console
$ HESTIA_S3=https://pub-<id>.r2.dev hestia serve --branch main
```

or in a workflow:

```yaml
      - uses: Mic92/hestia@v3
        with:
          s3: https://pub-<id>.r2.dev
```

Add the prefix if the writers use one (`https://pub-<id>.r2.dev/<repo>`).
The store is read only: `hestia gc` and any push need the `s3://` form with
credentials.

To use it as an ordinary substituter on a laptop, run `hestia serve` as
above and point Nix at it:

```console
$ nix build --substituters http://127.0.0.1:37515 --trusted-public-keys ...
```

## 6. Collect garbage

GC deletes what no root names anymore and needs the writing credentials, so
run it on a schedule. The action installs the binary and exports
`HESTIA_BIN`, and a job level `env` reaches both it and the `gc` run:

```yaml
on:
  schedule:
    - cron: "17 4 * * *"
jobs:
  gc:
    runs-on: ubuntu-latest
    env:
      HESTIA_S3: s3://hestia-cache
      HESTIA_S3_ENDPOINT: https://<ACCOUNT_ID>.r2.cloudflarestorage.com
      AWS_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY_ID }}
      AWS_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_ACCESS_KEY }}
      AWS_REGION: auto
    steps:
      - uses: Mic92/hestia@v3
        with:
          read-only: true # a GC job caches nothing itself
      - run: $HESTIA_BIN gc
```

R2 has no storage quota to stay under, so GC is about cost, not survival.
Every run rewrites the index, so a bucket nobody pushes to keeps working.

## Checking a store by hand

```console
$ curl -s https://pub-<id>.r2.dev/index | head   # head names, one per line
$ curl -sI https://pub-<id>.r2.dev/index         # cache-control: public, max-age=30
```

An empty or missing `index` is what a reader complains about when the URL
misses the prefix the writers use.

## What a public cache exposes

Everything in the bucket is readable by anyone who knows the URL: the store
paths you cached and their names. Heads are signed and every object is
content addressed and verified on read, so whoever serves the bucket, R2, a
CDN, a mirror, can withhold data but cannot forge it. A stale copy costs
cache misses, not trust.
