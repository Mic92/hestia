# Cloudflare R2 as the store

R2 has no egress fees, so the cache can be public: CI pushes with S3
credentials, everyone else reads over HTTPS without an account.

Public R2 buckets serve objects but refuse anonymous `ListObjectsV2`. Hestia
does not need it: writers keep an index of head names in the bucket and
readers fetch that one object. R2 supports conditional writes, so the index
is rewritten with a compare and swap and concurrent pushes cannot drop each
other's heads.

## 1. Bucket

```console
$ wrangler r2 bucket create hestia-cache
```

Its **Settings** tab shows the endpoint writers use,
`https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.

## 2. Credentials

**R2** then **API** then **Create User API token**, permission **Object Read
& Write**, scoped to the bucket. Store the access key ID and secret as
repository secrets.

## 3. Public reads

Settings, **Public Development URL**, **Enable**, confirm with `allow`. The
resulting `https://pub-<id>.r2.dev` is rate limited and uncached, so prefer a
custom domain for anything busy. Hestia's writes carry `Cache-Control`
already: a year and `immutable` for content addressed objects, 30 seconds for
heads and the index.

## 4. Push from CI

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write # for trust: same-repo or strict
    steps:
      - uses: actions/checkout@v6
      - uses: NixOS/nix-installer-action@main
      - uses: Mic92/hestia@v3
        with:
          s3: s3://hestia-cache
          s3-endpoint: https://<ACCOUNT_ID>.r2.cloudflarestorage.com
          trust: same-repo
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_ACCESS_KEY }}
          AWS_REGION: auto
      - run: nix build .#
```

R2 signs with `AWS_REGION: auto`. A bucket has no per-branch scopes, so
anyone holding the token can publish into any root: `trust` decides whose
heads readers believe, see [signing](signing.md). Repositories share a bucket
by prefix, `s3://hestia-cache/<repo>`.

Fork pull requests get no secrets. Give them the public URL instead.

## 5. Read without credentials

```console
$ HESTIA_S3=https://pub-<id>.r2.dev hestia serve --branch main
```

or as an action input, `s3: https://pub-<id>.r2.dev`. Append the writers'
prefix if they use one. Such a store is read only: pushes and `hestia gc`
need the `s3://` form.

## 6. Collect garbage

GC needs the writing credentials. The action exports `HESTIA_BIN`, and a job
level `env` reaches both it and the run step:

```yaml
on:
  schedule:
    - cron: "17 4 * * *"
jobs:
  gc:
    runs-on: ubuntu-latest
    env:
      HESTIA_S3: s3://hestia-cache
      HESTIA_S3_ENDPOINT: https://<ACCOUNT_ID>.r2.cloudflarestorage.com
      AWS_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY_ID }}
      AWS_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_ACCESS_KEY }}
      AWS_REGION: auto
    steps:
      - uses: Mic92/hestia@v3
        with:
          read-only: true
      - run: $HESTIA_BIN gc
```

Nothing evicts in R2, so GC only bounds the bill.

## Inspecting a store

```console
$ curl -s https://pub-<id>.r2.dev/index    # head names, one per line
$ curl -sI https://pub-<id>.r2.dev/index   # cache-control: public, max-age=30
```

A reader that reports a missing index is usually pointed at the wrong prefix.

Everything in a public bucket is readable by anyone with the URL, including
the names of the paths cached. Whoever serves it can withhold objects but not
forge them: heads are signed, everything else is content addressed and
verified on read.
